# EarthQuakeSensor

基于 **M5Stack Atom-Matrix（ESP32-PICO-D4 + 内置 MPU6886 六轴 IMU + 5×5 RGB LED）** 的振动 / 地震烈度传感器。

把它固定在任意刚性表面上，它会：

- 100 Hz 连续采样三轴加速度，识别"振动事件"；事件进行中把 **100 Hz 三轴原始波形（含触发前 15 s）分块流式上报**，事件时长不限；
- 在设备端用气象厅 **計測震度（JMA instrumental seismic intensity）** 算法把三轴振动收敛成一个物理量；
- 分解 **水平 / 垂直** 分量，记录峰值、RMS、时长，以及自适应分辨率的包络曲线（长事件全程覆盖）；
- 振动期间 LED 整屏红色快闪，平时全灭；
- 事件通过 WiFi 上报到局域网里的一个轻量 Flask 服务（明文 HTTP，复用一条 keep-alive 连接；OTA 走 HTTPS），配套网页看历史曲线；
- **所有检测门槛都能在网页上远程热调**，并实时回看噪声底 / 峰值遥测；**固件本身支持 WiFi 空中升级（OTA）**——设备装好后无论调参还是换固件，都无需再拆下来碰线。

> 注意：計測震度依赖安装点的机械响应（楼层、安装面、悬臂固定都会放大或衰减），所以设备原始读数是**安装点的体感强度**，并非地面烈度。设备永远上报原始值；服务端用一个可远程调的**安装点校正 `site_offset`**（計測震度减去它）把读数对齐到气象厅的地面震度，历史事件随校正值一起重算。实测一次标定见下文「标定记录」。

## 硬件

| 部件 | 说明 |
|---|---|
| MCU | ESP32-PICO-D4（双核 240 MHz，WiFi）|
| IMU | MPU6886，内部 I2C，±4g 量程，100 Hz |
| 显示 | 25× SK6812 RGB（5×5），事件时整屏红闪 |
| 量程选择 | ±4g：1g 重力 + 动态加速度，避免强振削顶（±2g 易饱和）|

采样率 100 Hz：地震主能量 < 10 Hz，远低于 50 Hz 奈奎斯特。

**抗混叠**：M5Atom 库初始化 MPU6886 时不配置加速度计 DLPF（默认 218 Hz 带宽、内部 1 kHz 采样），而我们只以 100 Hz 读取，50 Hz 以上的传感器噪声与高频机械振动会折叠进带内、抬高噪声底（实测约 2.3 gal）。固件在 `Init()` 之后把 `ACCEL_CONFIG2.A_DLPF_CFG` 设为 4（21.2 Hz），带外噪声不再混叠，JMA 通带（G(f) 在 10 Hz 已只剩 0.22）不受影响。

## 算法

### 1. 信号链（每个样本）
1. 读三轴加速度，转 gal（1 g ≈ 980.665 gal）。
2. **重力估计**：对原始加速度做慢速 EMA（时间常数 ~1.6 s）得重力向量 `g`。始终更新（不在事件期冻结），这样设备在振动中被移动后能重新收敛、事件才能正常结束。
3. **动态加速度** `d = raw − g`，合成幅度 `|d| = √(dx²+dy²+dz²)`。

### 2. 方向：水平 / 垂直分解
用重力单位向量把动态加速度分成：
- 垂直分量 `v = d·ĝ`（沿重力）；
- 水平分量 `h = d − v·ĝ`，幅度 `|h|`。

事件内分别记 **峰值水平 gal** 与 **峰值垂直 gal**。

### 3. 計測震度（JMA）—— 流式、不限时长
不依赖外部 DSP 库。官方滤波为频域 `G(f)`：

```
G(f) = FF(f) · FH(f) · FL(f)
  FF = 周期效应滤波   FH = 高频截止   FL = 低频截止(天然去掉重力 DC)
```

把 `G(f)` 逆变换成时域脉冲响应、截断为对称 **FIR**，对三轴动态加速度**逐样本卷积**（零相位）。

`a0` 定义为"使累计时间 `|a|≥a0` ≥ 0.3 s 成立的最大加速度"，等价于**滤波后矢量幅度第 `round(0.3·fs)` 大的样本**（100 Hz → 第 30 大）。"取第 K 大"用一个 **K 元素最小堆**在线维护，堆顶即 `a0`：

```
I = 2·log10(a0) + 0.94      (四舍五入到 0.1)
```

于是整段事件**内存恒定、不限时长**，且用的是整段最强 0.3 s（而非某个固定尾窗），长事件不会低估。FIR 由同一个 `G(f)` 导出，主机端以频域 FFT 实现为 oracle **对拍验证**（多种波形震度完全一致）。滤波增益解析校验：`G(0.5)=1.1234`、`G(1.0)=0.9964`、`G(10)=0.2235`。

計測震度 → 震度阶级：

| 計測震度 I | 震度 | | 計測震度 I | 震度 |
|---|---|---|---|---|
| < 0.5 | 0 | | 4.5–5.0 | 5弱 |
| 0.5–1.5 | 1 | | 5.0–5.5 | 5強 |
| 1.5–2.5 | 2 | | 5.5–6.0 | 6弱 |
| 2.5–3.5 | 3 | | 6.0–6.5 | 6強 |
| 3.5–4.5 | 4 | | ≥ 6.5 | 7 |

### 4. 安装点校正（服务端）与标定记录
设备上报的是安装点原始計測震度；服务端配置项 `site_offset`（可在网页调）给出**校正后計測震度 = 原始 − site_offset**（保留 1 位小数、下限 0），列表/详情/告警都以校正值为主、原始值并列。因为原始值照存，改校正值后历史事件也即时重算——每来一次有官方震度可对照的地震都可以再标一次。

| 日期 | 地震 | 最近官方观测点 | 设备原始 | 校正值 |
|---|---|---|---|---|
| 2026-08-23 02:00 JST | 茨城県南部 M5.9（最大震度 5弱）| 东京都内、距安装点 1 km 内的两个气象厅观测点均为 3（再远一点有 4）| 4.3（震度 4）| `site_offset=1.0` → 3.3（震度 3）|

安装点：低层 RC 公寓的上层楼面，设备固定在插在约 1.5 m 高墙插上的 USB 充电器侧面。用事件包络重建波形、过同一套算法（流式 FIR 与 FFT oracle 双算）得 4.2–4.4，与设备一致——偏差来自楼层 + 悬臂安装的机械放大，不是计算误差。

### 5. 事件状态机
- **抗污染噪声底**：空闲时每秒算一块 `|d|` 均值，保留最近 120 块，取 **20 分位**作噪声底；事件期间冻结。
  不用 EMA 的原因：地震 P 波比 S 波早几秒到几十秒到达、幅度小却高于底噪，5 s EMA 会被它抬高数倍，触发阈值跟着飙升，S 波触发后尾波很快"低于阈值"被提前切掉（2026-08-23 实震：噪声底 0.9→5.7 gal、阈值 34 gal，12–31 gal 的尾波全丢，只记到 10 s）。分位数只要窗口内 20% 的时间安静就不受污染（可容忍 96 s 前驱振动），环境真变化 2 分钟内仍跟上。
- **起停双阈值（迟滞）**：
  - 触发 `thr_on = max(K × 噪声底, floor_min)`：连续 ≥3 样本超过 → 开事件（去抖）；
  - 收尾 `thr_off = max(k_off × 噪声底, floor_off)`（自动不高于 `thr_on`）：触发后只要还超过它就算仍在震，连续 `holdoff_s` 低于它才收尾——尾波留得住；
  - `tail_max_s`：强晃（超 `thr_on`）停止后最多再记录这么久，兜底防旁边持续走路让事件收不了尾。
- 事件报两个时长：`strong_s` = 强晃跨度（起点→末次超 `thr_on`），`dur_s` = 全程跨度（起点→末次超 `thr_off`）。
- **两道录入门限**（滤掉脉冲式干扰，如脚步/敲击）：
  - `min_dur_s`：**强晃跨度** `strong_s` 短于此值不入库（轻碰的余振虽超收尾阈值，也拦得住）；
  - `min_keisoku`：計測震度低于此值不入库。
- **LED** 跟强晃：`strong_s` 达 `led_min_s` 即闪，强晃停 `holdoff_s` 即灭（记录可继续在尾波里进行，不会红灯闪几分钟像故障）。
- **自适应包络**：起步每 100 ms 记一格（总幅度/水平/垂直峰值）供网页画曲线；点数达上限即**格宽翻倍合并**，任意长度事件都全程覆盖，仅时间分辨率自适应变粗（每条事件回报实际格宽 `env_dt_ms`）。
- **起止时刻**：事件起止由采样计数经"时间锚"（一对 `(样本序号, epoch ms)`，空闲时刷新）折算成 epoch 毫秒（`start_ms`/`end_ms`，秒值 `start_ts`/`end_ts`），不受 hold-off 与队列/网络延迟影响；同一事件里波形块与摘要的时刻出自同一个锚，严格一致。

### 6. 原始波形流式上报
采样核把每个样本的 **三轴 int16 原始 ADC**（±4g → 8192 LSB/g，无损）写进 60 s 环形缓冲（36 KB，SPSC 无锁）。事件强晃跨度一达 `min_dur_s`（确定不会被时长门限丢弃），网络核即开始上报：先补传**触发前 15 s**（P 波在这里），之后每满 5 s 发一块（3000 B 二进制 `POST {base}/wave?mac&ev&seq&t0&fs&n&lsb_g`），事件结束后把余下的发完。

- 块先写进 flash 的专用 **`wavelog` 分区（1 MB，见 `firmware/partitions.csv`）**，再由网络核按记录号顺序上传：**断网时块留在 flash，联网后自动补传；断电后开机扫描分区恢复未发记录**。每块独占一个 4 KB 扇区，"已发"标记靠 NOR flash 位只能 1→0 的特性改写头部一个字段、无需擦除；擦除只在空闲时每 5 s 零散做一个扇区（擦除会让 IDF 停住采样核 ~45 ms），事件中只做 ~1 ms 的页写。日志可存 256 块 ≈ 21 分钟，写满环绕覆盖最旧。
- 事件**时长不限**——内存环只需吸收落盘延迟；块自带真实时刻，若上报落后被覆盖，服务端能标出缺口。
- 离线期间事件摘要进 NVS（只存标量），联网补发；其包络由服务端从补传的原始波形重建（详情里 `env.from_wave=true`）。
- 块以 `(mac, ev = 事件起点 epoch ms, seq)` 标识，摘要的 `start_ms` 与 `ev` 同源同值，服务端据此关联；被门限丢弃的事件没有摘要，其块成为孤儿，1 h 后清理。
- 服务端提供 `GET {base}/event/<id>/wave.json`（原始 ADC + 逐样本毫秒时刻 + 缺口）与 `wave.csv`（gal，含重力）；网页画三轴去均值波形并可下载 CSV。
- 有了原始波形，服务端可用 FFT oracle 重算計測震度与设备流式值对拍、做频谱/卓越周期分析——包络只是给网页看的缩略图。

## 固件架构

双核分工，保证振动期间绝不漏采样：

- **采样任务（core 0，高优先级）**：读 IMU → 喂检测器 → 驱动 LED → 发布遥测 → 把结束的事件入 FreeRTOS 队列。**绝不被网络阻塞**。
- **主 loop（core 1）**：WiFi 维护、NTP 对时、取队列 HTTP 上报、心跳遥测（响应带回远程配置）、断网补发。

可靠性：
- **断网补发**：上报失败的事件以精简形式（仅标量，不含包络，省 NVS）存 NVS 环形缓冲，重连后批量补发；服务器按 `(mac, start_ts)` 唯一索引幂等去重。原始波形走 flash 日志分区（见上），断网/断电都不丢（日志容量 21 分钟内）。
- **远程配置热更新**：开机拉一次 `/config`，之后随每 15 s 一次的心跳响应下发（省掉单独拉配置的请求；ArduinoJson 解析），经临界区在采样任务安全点应用，并写 NVS 缓存（断网/重启沿用，联网后服务器为权威源）。
- **WiFi 不省电**：关闭 modem sleep（设备插墙电；开着省电时 AP 要替它缓存下行包，一次 TLS 握手被拖到约 1 s，同一 AP 上的其它 2.4G 终端跟着卡顿）。
- **OTA 空中升级（长按按钮触发）**：长按顶部按钮 3 秒 → 拉 `/config` 比对服务器广播的版本，不同则 HTTPS 拉取新 `.bin`、写入备用分区并重启。LED 指示：检查时**蓝灯常亮**、升级中**蓝灯闪**、每次正常启动**绿灯闪一下**。双 OTA 分区（各 1.44 MB，自定义分区表）+ **启动确认/超时自动回滚**（新固件联网成功才提交，否则回滚旧版）——装好后换固件也无需碰线。
- **联网栈**：上报（事件、波形块、心跳、配置）走局域网明文 HTTP，所有请求复用一条 keep-alive 连接，每 15 s 的心跳只是一来一回两个小包。早先每轮新建 TLS 连接，握手要下发约 5 KB 证书，设备离 AP 远时会长时间占住 2.4G 空口、拖慢同一 AP 上的其它终端。复用的连接若已被服务器关掉，换新连接重发一次（事件、波形块服务端幂等）。服务器的 keep-alive 超时要大于 15 s。OTA 仍走 HTTPS（`WiFiClientSecure`），其 TLS 握手远超默认 8 KB 的 loop 任务栈，故 `SET_LOOP_TASK_STACK_SIZE(16384)` 把栈加到 16 KB。

## 远程配置与遥测

所有检测参数都可在运行时通过网络热更新（装好后无需拆机重刷）：

| 参数 | 含义 |
|---|---|
| `floor_min` | 触发下限（gal）|
| `k` | 噪声倍数，阈值 = max(k×噪声底, floor_min) |
| `holdoff_s` | 低于阈值持续多久收尾 |
| `min_dur_s` | 录入门限：振动跨度下限 |
| `led_min_s` | LED 门限：振动跨度达此值才闪 |
| `min_keisoku` | 录入门限：計測震度下限（设备原始值）|
| `k_off` | 收尾阈值噪声倍数，收尾阈值 = max(k_off×噪声底, floor_off) |
| `floor_off` | 收尾阈值下限（gal），尾波低于此值才算停 |
| `tail_max_s` | 强晃停止后最多再记录的秒数（兜底）|
| `site_offset` | 安装点校正（仅服务端生效，固件忽略）：显示/告警震度 = 原始 − 此值 |

设备心跳同时回报**当前噪声底**、**最近窗口峰值 gal**、**固件版本**、**剩余堆/历史最低堆**、**波形环秒数**、**flash 日志待补传块数**，以及**实际生效的配置**——网页据此引导按现场实测噪声设门槛，并确认配置已下发到位。服务器可在 `/config` 与心跳响应里广播新固件版本；**长按设备顶部按钮 3 秒**即检查并升级到该版本（非自动，避免设备擅自更新）。

## 服务端与网页

轻量 Flask 服务（SQLite 存储）。下表 `{base}` 即固件 `REPORT_BASE`（上报 API 的基址，由你在 `config.h` 配置；`/firmware` 由设备经 `OTA_BASE` 走 HTTPS 访问）：

| 方法 & 路径 | 作用 |
|---|---|
| `POST {base}` | 收事件（单条/数组），幂等去重 |
| `GET  {base}/events` | 事件列表（省略包络重数据）|
| `GET  {base}/event/<id>` | 事件详情（含自适应包络 + 原始波形元信息）|
| `GET  {base}/event/<id>/wave.json` | 原始三轴波形（int16 ADC + 逐样本 epoch ms + 缺口）|
| `GET  {base}/event/<id>/wave.csv` | 原始波形 CSV 下载（gal，含重力，毫秒时刻）|
| `POST {base}/wave?mac&ev&seq&t0&fs&n&lsb_g` | 收波形块（体为 int16 LE 交错 x,y,z；幂等覆盖）|
| `DELETE {base}/event/<id>` | 删除单个事件（连同波形）|
| `POST {base}/heartbeat` | 设备心跳（在线 + 遥测 + 生效配置 + 固件版本）；响应同 `GET /config`（下发当前配置 + OTA 广播）|
| `GET  {base}/status` | 各设备最近心跳 |
| `GET/POST {base}/config` | 读取 / 保存检测参数（GET 可附带 OTA 版本广播）|
| `GET  {base}/firmware` | OTA：下发固件 `.bin`（只读）|
| `GET  {base}` | 网页面板 |

网页：包络曲线（总幅度/水平/垂直）+ **原始波形**（三轴去均值，逐像素列取 min/max 保峰值，灰带标触发前段与缺口，可下载 CSV）+ 事件列表（震度色块/峰值/水平/垂直/时长）+ 删除；右上角齿轮弹出**检测参数设置**与**实时遥测**。

> 服务端纯函数（震度→阶级映射、payload 归一化/校验、配置夹取）均无副作用，配有 pytest。

服务端（Flask 路由 + 网页 + pytest）在另一仓库维护，本仓库聚焦固件与算法。

## 编译与烧录

依赖：Arduino 1.8.19 CLI + `m5stack:esp32` 2.1.4 core（含 ArduinoJson 库）。

```bash
cp firmware/config.example.h firmware/config.h   # 填 WiFi/服务器地址
cp device.conf.example device.conf               # 填工具链路径 + 你的设备 by-id 烧录目标

./build.sh        # 只编译
./build.sh -f     # 编译 + 烧录
./build.sh -w     # 只烧已有 bin
```

**防刷错**：`build.sh` 把烧录目标写死为 `device.conf` 里的 by-id 路径（`/dev/serial/by-id/...`，不随枚举顺序变），并显式拒绝解析到 `ttyUSB0`/`ttyACM0` 等别的板子；目标不在位就报错退出，绝不回退到别的端口。

接上设备后用 `ls -l /dev/serial/by-id/` 找到对应条目，填入 `device.conf` 的 `EQ_FLASH_TARGET`。

> 分区表是 `firmware/partitions.csv`（双 OTA 分区各 1.44 MB + `wavelog` 1 MB 波形日志），被 core 自动采用；`build.sh` 会校验 bin 装得进 app 分区。分区表只能靠线刷设置，**首次必须线刷**，之后即可走 OTA。

## 测试

DSP/检测器是纯 C++17、不依赖 `Arduino.h`，固件与主机共用同一份源码：

```bash
cd test && make all    # g++ 编译运行 test_jma + test_jma_stream + test_detector + test_wavering + test_wavelog
```

- `test_jma`：用解析滤波增益和已知波形当 oracle，校验 FFT + 計測震度计算；
- `test_jma_stream`：流式 FIR 实现与频域 FFT oracle 对拍，并验证长事件不限时长、强震段在前不被尾窗丢弃；
- `test_detector`：持续振动触发、脉冲不入库、最小震度门限、运行期改配置生效、移位后事件能正常结束、自适应包络全程覆盖；以及实震形态回归（底噪 → P 波前驱 → S 波 → 指数衰减尾波：噪声底不被前驱污染、尾波全程记录 `dur_s≈35 s`、LED 跟强晃、`tail_max_s` 兜底、轻碰余振不入库）；
- `test_wavering`：环缓冲回绕、覆盖检测（返回 −1）、流式按块消费无丢失、断传超容量后跳到最旧继续；
- `test_wavelog`：用内存 NOR 模拟器（位只能 1→0、可注入"写到第 k 字节断电"）验证：追加/标已发不擦除、重启后未发记录恢复且写指针/记录号接续、半写扇区判坏并回收、空闲擦干净后事件中零擦除、写满环绕覆盖最旧、补传顺序与失败重试。
